# Implementation verification

Verified locally on October 4, 2026. Existing wardrobe data was not used for generation or modified by these checks.

- `sfw pnpm check`: 100 passing tests and a production frontend build.
- Docker Compose builds on Linux ARM64; a separate Linux AMD64 image also builds.
- The initial 24 server tests also passed inside the production Node 22 Linux image; the expanded 88-test suite was verified locally. The Vite proxy test runs with development dependencies. The container tests cover multipart import, single-request queue execution, optional modeled photos, concurrent edits, deletion protection, SSE, explicit migration, job recovery, output reuse, complete data snapshots, simulated S3 outages, and verified safe restore.
- A disposable production container serves the frontend and health endpoint and stops cleanly. The pinned native Codex app-server initializes on both ARM64 and AMD64, reporting available and disconnected without an API key.
- Browser checks use isolated test data and a synthetic image. Photo-library selection, preview, multipart upload, manual entry, crop editing and recovery after page reload work while disconnected. Phone layouts at 360, 390 and 430 pixels and desktop at 1280 pixels have no horizontal overflow in the checked views. The native camera input uses `capture="environment"`.
- Read-only compatibility checks resolved existing library image references. Missing outfit/settings manifests are initialized when the application starts; existing IDs and records are retained.
- Review regressions cover newer garment replacements, approved/deleted outfit preservation during receipt replay, PNG-only checkpoint recovery, logout and cancellation ordering, stale cleanup, backup destination changes, and staging cleanup after status-write failures. The development proxy permits matching browser origins and continues rejecting foreign origins.
- Additional review regressions cover data-only recovery after image/analysis pointer writes fail, explicit regeneration, missing operational images, isolated recovery failures, legacy chroma-cleanup migration, and remote import updates that preserve unsaved fields. Save acknowledgements accept normalized metadata while preserving edits made during a pending save. Temporary test servers stop when each test completes; the Wardrobe server is left stopped after testing.
- A final browser check with a disposable production server confirmed that remote name/crop changes refresh untouched import fields, crop preview preserves remote metadata, and an unsaved local name survives later remote color/crop updates. The disposable server is stopped afterward.
- Import metadata commits revalidate metadata, source and job/stage state after crop processing. Concurrent-edit and cancellation regressions verify that stale requests return 409 without changing the newer crop or metadata; retrying against the current record preserves both devices' unrelated edits.
- Gallery save acknowledgements adopt server-normalized names and tags while preserving fields changed during the request, so a successful save does not leave unchanged fields marked as unsaved. A disposable production browser check confirmed saving `LINEN` displays `linen` and allows the viewer to close without an unsaved-changes warning; that server stopped cleanly.
- Gallery drafts merge untouched remote fields against their last server baseline and save only edited fields. Regression coverage preserves remote tags even when a second update precedes its browser event. A disposable production browser check confirmed an unsaved local name survived remote color/tag changes, saving preserved all three values, and closing did not report unsaved changes; the server stopped afterward.
- Queue candidates are revalidated under the write lock before claiming a stage. Tests cover manual entry during authentication refresh, fresh generation superseding a recovered old receipt, and shutdown during refresh. Cancelled processing stages become retryable only after the native turn and late image checkpointing finish; explicit retry reuses any completed output without another AI request.
- Pieces, Settings and Outfits discard older overlapping refresh responses; gallery mutations also invalidate pending reads and fetch current state. Regression tests cover late reads/errors and saved/deleted items. A disposable production browser check held an old initial gallery response, applied a remote rename, then released the old response; the newer name remained visible.
- Operational directories are resolved to their real filesystem locations before startup accepts them. Tests reject state aliases into data or its ancestors, aliases in each operational child directory, and direct backup staging aliases into data; separate external aliases remain supported.
- Import preview and approval submit only edited metadata fields. A regression preserves another device's unseen color, tags and crop while saving a local name. A disposable production browser check confirmed both stored metadata and the editor retained all four values after delayed refreshes were released. All disposable servers were stopped afterward.
- Crop, garment, modeled-image and outfit approvals require the reviewed image URL; cleanup acceptance requires its reviewed raw source. Regression tests reject stale replacements and preserve newer results. Crop metadata responses describe the edit committed under the write lock, so a concurrent replacement cannot silently advance approval to an unseen image. A disposable production browser check confirmed edited-crop approval, rejection after an unseen garment replacement, successful approval after refreshing the review, and outfit-photo approval; the server stopped cleanly.
- The worker and native image smoke test share garment background validation. Tests verify that one partially transparent pixel or transparent padding cannot bypass chroma removal, native transparent edges and garment colors survive framing, and opaque non-chroma images fail explicitly. An end-to-end synthetic import also verifies saved raw output, exposed cleanup diagnostics and a clean accepted image.
- Failed garment and modeled-image stages expose regeneration and replacement uploads, including failures with no usable chroma source or saved image. Cleanup controls require a usable raw source and chroma key; regeneration and replacement invalidate obsolete cleanup state. Six regression tests cover those recovery paths and partial photo batches, which acknowledge each successful upload before sending the next and retain only failed/unattempted photos for retry. Remaining photo previews are retained as acknowledged photos are removed. A disposable production browser check confirmed rejected-image recovery through regeneration, review and approval, and a separate check of the production upload handler confirmed retries did not duplicate acknowledged imports. All temporary servers stopped afterward.
- Completed images and structured analysis results are written to `data/` even when operational receipt writes fail. Three regressions simulate receipt PNG/JSON failures, create real snapshot archives using simulated S3, verify the saved output survives restore into a new directory, and finish the restored job with a fresh state directory while disconnected without another AI call. Existing tests continue verifying operational-checkpoint recovery when data ingestion or job-pointer writes fail.
- A build with UID 1001 and GID 100 succeeds even though that group ID already exists in the base image. Its non-root runtime serves the production frontend and health endpoint, initializes native app-server without credentials, and shuts down cleanly. Root UID/GID values are rejected at build time.
- A local import exposed removal of `readOnly.access`. The adapter now selects a named scratch-only read profile and uses `never` instead of the unsupported `untrusted` approval policy. A native 0.149.1 regression creates the production thread with an isolated credential-free home and confirms the active profile and read-only/no-command-network sandbox, stopping before inference. Simulated turns validate the same permissions selection for analysis and image generation.
- Development uses independent monitors for backend and frontend process groups on macOS/Linux. Vite starts directly, avoiding nested sfw/pnpm wrappers that create separate groups. Five regressions launch disposable HTTP listeners through a real Node watcher and a simulated frontend with a child listener, then verify SIGINT, SIGTERM, SIGHUP, SIGKILL of the launcher and watcher exit stop both services. Optional `.env` loading is exercised with and without a file. A disposable PTY smoke test through the installed SocketFirewall wrapper and real Vite confirmed actual Ctrl+C leaves no server, watcher, Vite or monitor processes. The fixture used the cached pnpm 10.33.2 runner after declining pnpm 11's request to reinstall the symlinked dependency tree; no dependencies were reinstalled. Every test process stopped afterward, and ports 3000/5173 were verified closed.
- Development enables timestamped backend logs alongside inherited Vite stdout/stderr. Four logging regressions cover credential/image redaction, chunked and oversized native diagnostic lines, Codex event/RPC summaries and failures without protocol payloads, and HTTP/import/backup logs using isolated data and simulated AI/S3. Launcher regressions also confirm backend logging is enabled and stdout/stderr from both services reach the terminal. Browser console output remains in browser developer tools.
- A local native-image turn failed with the runtime diagnostic `code-mode host is disabled`: GPT-5.6-Sol's tool catalog uses `code_mode_only`, so native image calls require that host. The adapter now enables `code_mode_host` while retaining disabled shell/apps/plugins/browser tools and restricted read permissions; simulated thread requests assert those settings. A subsequent local request used included ChatGPT usage, emitted native image-generation events, and saved raw output and a 1024x1024 transparent cutout under `data/`. The cutout contained transparent background and visible garment pixels with zero reported chroma contamination, and reached review without automatic approval or a modeled-photo request. No API key or desktop image-generation tool was used. Personal source photos and generated outputs are excluded from Git and Docker build contexts.

- Account refreshes commit only when their request and authentication generation are still current. Seven regressions cover delayed account/model/usage responses, stale errors, logout, connection notifications and delayed device-login results; an additional HTTP regression prevents a connection event from resuming the queue during pause persistence. Logout clears account metadata and suppresses refreshes while disconnecting. These cases use simulated account responses and disposable credential fixtures.
- Empty garment detections remain active with an explanatory error and manual entry, fresh analysis retry, source download and cancellation. Four regressions cover manual import through approval, fresh analysis instead of replaying an empty receipt, and startup recovery of previously hidden jobs for manual entry and retry. A disposable production browser check confirmed the error and actions remain available after reload and manual entry opens the saved crop without reuploading. The test tab and server were closed afterward.
